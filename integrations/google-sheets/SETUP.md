# Подключение результатов Digital Hub

Нужны ваша Google Таблица и право редактировать её, Google Apps Script и аккаунт Vercel. Таблицу не нужно публиковать или открывать по ссылке для всех.

## 1. Приёмник в Google

1. В целевой Google Таблице: **Расширения → Apps Script**.
2. Вставьте содержимое `Code.gs` этого каталога. Не заменяйте чужой существующий скрипт: используйте новый проект, если в таблице уже есть автоматизация.
3. В **Project Settings → Script Properties** добавьте:
   - `SPREADSHEET_ID`: часть адреса таблицы между `/d/` и `/edit`.
   - `WEBHOOK_SECRET`: случайный секрет, минимум 32 символа. Для генерации локально можно выполнить `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"`. Секрет не публикуйте и не добавляйте в исходники.
4. **Deploy → New deployment → Web app**. Execute as: **Me**. Who has access: **Anyone**. Доступен только endpoint; сам документ остаётся закрытым. Запись возможна только при корректной HMAC-подписи от сервера Vercel. GET не возвращает содержимое таблицы.
5. Разрешите скрипту доступ к таблице через штатное окно Google от своего аккаунта. Если политика организации запрещает такой тип Web app, публикация будет заблокирована: потребуется согласование с администратором или отдельная интеграция Sheets API.
6. Скопируйте URL, заканчивающийся на `/exec`, не `/dev`.

Скрипт создаёт лист «Результаты Digital Hub» внутри заданного документа при первой корректной отправке. Существующие листы не изменяет. Если лист с этим названием уже существует, проверяет заголовки и отказывается писать при несовпадении. ID и контрольную сумму в первых двух колонках не редактируйте: они нужны для защиты от дубликатов.

## 2. Подключение Vercel

В проекте Vercel → **Settings → Environment Variables**:

- `GOOGLE_SHEETS_WEBHOOK_URL` — URL `/exec`.
- `GOOGLE_SHEETS_WEBHOOK_SECRET` — то же значение, что `WEBHOOK_SECRET` в Google.

Обе переменные серверные. Не используйте `NEXT_PUBLIC_`. Отметьте Production и выполните новый деплой. Для локальной проверки — те же имена в `.env.local` (файл исключён из git).

Настройки сборки: Next.js; `npm run build`; стандартный Output Directory. Удалите старую настройку `out`, если она была задана для первой статической версии.

## 3. Проверка после деплоя

1. Откройте публичный Vercel URL и `/questionnaire`.
2. Проверьте, что предупреждение о неподключённой таблице исчезло.
3. Пройдите опрос с именем «ТЕСТ — удалить», группой «TEST» и email `test@example.com`.
4. Дождитесь «Результат записан» и сверьте ID с первым столбцом таблицы. В строке должны быть 8 числовых шкал, практические ответы, рекомендации и 30 ответов.
5. Повтор того же запроса с тем же ID должен возвращать успех без второй строки. Новый ID означает новое прохождение.
6. Тестовую строку можно удалить вручную после проверки.

## Обслуживание

После редактирования `Code.gs` обновляйте deployment на новую версию, сохраняя URL. При изменении схемы вопросов обновляйте версию, заголовки и число колонок на сервере и в скрипте совместно; перенос данных выполняйте отдельно. Не удаляйте строки реальных кандидатов в ходе тестирования.

В Google хранится 55 колонок: ID, контрольная сумма, дата, версия, имя, группа, email, согласие, название профиля, 8 шкал, нагрузка, формат команды, дедлайны, расписание, стиль, интерес, роли, рекомендации, 30 ответов.

Apps Script имеет квоты; скрипт рассчитан на небольшой университетский набор. Ошибки сервиса не маскируются успехом. Удаление и исправления реальных заявок выполняет куратор по ID. Срок хранения и круг редакторов таблицы определяет университет до начала сбора.

Документация: [Google Web Apps](https://developers.google.com/apps-script/guides/web), [LockService](https://developers.google.com/apps-script/reference/lock/lock-service), [Vercel Environment Variables](https://vercel.com/docs/environment-variables).
